## THE CENTRAL ARCHITECTURAL INSIGHT: EPHEMERAL TASK RUNS
Render docs: each task run executes in its **own ephemeral container**, spun up per run and
deprovisioned when the run completes. Cognee's DEFAULT graph backend is **file-based** (ladybug,
under SYSTEM_ROOT_DIRECTORY/DATA_ROOT_DIRECTORY, inside site-packages).
=> A file-based graph written in an `ingest` task run is DESTROYED with that container, so a later
   `retrieve` task run finds nothing. **THIS IS WHY NEO4J IS IN THE ORGANIZER'S STACK** — it is not
   a fancier choice, it is the only way to get memory that survives across ephemeral task runs.
=> Design rule: the graph must live OUTSIDE the containers (Neo4j / networked store), OR the graph
   must be pre-built and baked read-only into the image.
=> Also: first invocation of a task includes container spin-up + image pull, so it is slower.
   WARM every task you plan to demo before judges arrive.
