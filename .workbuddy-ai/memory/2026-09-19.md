## VERIFIED COGNEE API DETAIL (from docs)
- `await cognee.remember(data, dataset_name="docs")` -> permanent memory (add -> cognify -> improve)
- `await cognee.remember(text, session_id="sales_chat_1")` -> session memory (fast short-term cache)
- `await cognee.recall(query_text=...)` -> answer; Cognee's own site shows answers WITH CITATIONS
- Built-in graph view ships with Cognee (no build needed) — the free wow moment
- `run_in_background=True` -> async ingestion, returns RememberResult to await later
- `dry_run=True` -> token/cost estimate with NO LLM calls (safe to test without a key)
- `node_set=["tag"]` -> tag ingested content for retrieval organisation
- `raise_on_error=False` -> returns status="errored" instead of raising CognifyFailedError
- Feature flags OFF by default: `CONTRADICTION_DETECTION=true`, `PROVENANCE_TRACKING=true`
- Cognee company-brain flow is literally "Connect. Build. Ask." — matches PS-2 exactly

## THE KEY MYSTERY, SOLVED
The user's "cognee key" (`a6de47945a4e...c949cd5`, 64 hex) is a **Cognee Cloud
MANAGEMENT key**, not a model-provider key.
- As `LLM_API_KEY` -> `litellm.AuthenticationError: Incorrect API key provided` (OpenAI).
  It IS read correctly (config showed len=64) — OpenAI simply rejects it.
- It works here, and only here:
    GET https://api.aws.cognee.ai/api/tenants/current        X-Api-Key -> 200 (401 without)
    GET https://api.aws.cognee.ai/api/tenants/current/service-url
  -> tenant `Personal Workspace` (5ac9a1e8-fdc4-49da-8f91-05756c13ad17), status active
  -> service URL https://tenant-5ac9a1e8-fdc4-49da-8f91-05756c13ad17.aws.cognee.ai
- NOT a `ck_...` key (that is the tenant-instance format; `cognee serve` cloud mode uses
  Auth0 device flow). Raw hex works on the MANAGEMENT API only.
- **CONSEQUENCE: no LLM_API_KEY is needed at all.** The tenant instance owns the model,
  embeddings, vector store and graph. Verified healthy: postgres + pgvector + graph + s3.

## FOUR TRAPS THAT COST REAL TIME (all fixed + commented in code)
1. `dataset` / `dataset_ids` query params take a **UUID**, not a name -> 422 uuid_parsing.
   Fixed with `resolve_id()`.
2. Terminal pipeline state is `DATASET_PROCESSING_COMPLETED`. An exact match on
   `'"completed"'` never fires and the poll loops to timeout. Fixed with `_is_terminal()`.
3. **Querying mid-ingest returns a confident WRONG answer, not an error.** Measured: it
   invented "$39 per year" for a $420,000 contract. Fixed with `wait_ready()`.
4. Config read at import time breaks any caller that loads `.env` afterwards. Fixed by
   making every accessor lazy + `load_env()` on import of cognee_cloud.

## ALSO LEARNED
- `graph-summary` returns numNodes 0 until a summary run is computed -> use `/graph` for
  counts instead (it returns real nodes/edges).
- Citations arrive INLINE in the answer text as an "Evidence:" block, not in a
  `references` field -> `split_evidence()` parses it out for the UI.
- Dropped `cognee` from requirements.txt: the deploy talks HTTP to the cloud tenant, so the
  huge local SDK tree (torch etc.) is unnecessary. Bigger win than it sounds.
- `cognee`/`neo4j` still installed in the local venv `envs/hackathon` (used for early
  `cognee-cli demo` offline verification).
