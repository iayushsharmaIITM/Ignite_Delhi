# Bug hunt — answer engine and UI, 2026-10-05

Scope: the whole of `app.py` + `orchestrator.py` + `memory_layer.py` + `citations.py`
+ `auth.py` + `lifecycle.py` on the engine side, and all of `frontend/src` plus the
`index.html` bundle guard on the UI side. Method: three independent read-only passes
(two parallel hunters with disjoint briefs, then every surviving claim re-opened and
read at the cited lines before it was believed). Nothing here is a style opinion;
each entry names the file:line, what it contradicts, and what a user experiences.

Twenty-six defects found. **Fifteen fixed in this pass, one proven to be a
non-issue, ten reported for your decision** — the split and the reason for each is
in the status line. Two entries below (U4, U13) were written as fixed and then
verified as *not* landed before commit; they are marked open, because a report that
overstates its own fixes is the thing this round was hunting for.

Two counts to hold in mind: the engine had **already-written features that were
switched off by an ordering mistake**, and the UI had **already-correct patterns that
one call site skipped**. Almost nothing here needed new invention; it needed the
discipline the codebase already contains applied to the place that missed it.

---

## Part 1 — the answer engine

### E1 · HIGH · A greeting in the real app paid a full retrieval round trip
`app.py` prepended the browser's `[Client local time: …]` note to `q` and *then*
called `memory_layer._is_smalltalk(q)` on the mutated string. The detector's own
all-tokens rule failed, so "hi" from the shipping UI was answered by 11–25 s of
embed + graph search rather than by the instant template that already existed.
Measured: nine of nine common greetings returned `False` with the prefix, `True`
without it.

**Fixed.** Classification now runs on the caller's own words before anything is
attached, the detector ignores the note regardless (`phatic.strip_system_note`), and
a new hermetic tier (`tests/test_phatic.py`, 38 checks) asserts the argument the
classifier receives. `verify.sh` runs it; `--quick` includes it, so CI does too.

### E2 · HIGH · The local-time hint was built and then thrown away
The same line had a second half: `q` was reassigned and **never read again** —
`recall()` is called with `question`, built from the un-prefixed value. Proven by
AST walk, not by eye. So "what time is it?" reached the model with no timezone at
all and was answered from `orchestrator._direct_chat_general`'s
`datetime.now() … "local time"` — the server's clock, confidently mislabelled.

**Fixed.** The note is now attached to `question` (what the model actually reads),
and `tz` is plumbed to the phatic table so a greeting says *Good evening* to the
person for whom it is evening, resolved with stdlib `zoneinfo` and never raising on
an unknown zone.

### E3 · HIGH · A retrieval that succeeded and found nothing was reported as an outage, and the "outage" answered with fabricated citations
`orchestrator.py` recorded a result only when the text was non-empty
(`if text.strip() and results is None`), so an empty-but-successful completion left
`results is None` → `raise RuntimeError("both retrieval agents failed")` →
`memory_layer` caught it with `produced == False` → fell back to
`fixtures/answers.json`, **whose entries carry hand-written citation chips naming
real contract files**. The invariant is "no fabricated citations, ever";
`citations.py:9-11` names this exact fallback as the reason it exists. The error was
also wrong in its own terms — the message blamed two agents when the hedge design
starts only one.

**Fixed.** A completion that returned no content is now recorded as what it is, and
the engine says so: *"I found nothing in this brain that answers that. I only say
what your documents say, so there is no source to cite here."* with no references.
The raise is reserved for a real failure (`errored > 0`).

### E4 · HIGH · `POST /api/jobs/{id}/cancel` had no tenant check
Any signed-in caller could cancel any job by id: `require_tenant` then straight to
`lifecycle.request_cancel`, whose UPDATE carries no workspace predicate. Ids are not
secret — they are echoed in `SlugConflict` and idempotency payloads and log lines —
so guessing one cancelled another workspace's build and set `brains.state = FAILED`.
The **GET on the same resource does check**, and `app.py:75-77` publishes "Every
read/write route is tenant-scoped: knowing an id is not ownership." A malformed id
also reached Postgres and 500'd.

**Fixed.** The cancel route now mirrors its sibling exactly: UUID validated first
(malformed → 404, never 500), org ownership checked in clerk mode (foreign → 403),
and `requested: true` is no longer hardcoded — a job that does not exist or already
finished returns 404 instead of a success-shaped lie.

### E5 · MEDIUM · A Postgres outage was reported to the usage screen as "no recorded calls"
`/api/usage` returned `{"ok": false, "usage": []}` when the database was down, and
had no `except storage.db_error` at all, so a mid-life outage raised to the generic
500. AGENTS.md: *"A storage outage must surface as 503, never as an empty list."*
The historical reason recorded in `BUGS_AUDIT.md` ("the legacy shell renders `[]` for
any non-OK") expired when the legacy shell was deleted, and the one consumer that
remains renders a 503 reason honestly.

**Fixed.** Both paths now `storage.mark_down(...)` and raise 503 with the server's
own words. A claim about spend is never made from an unavailable ledger.

### E6 · MEDIUM · `/api/extract` read an attachment of unbounded size into memory
`data = await upload.read()`, with the size check applied later inside
`documents.extract` — after the bytes were resident. `_read_capped` exists in the
same file specifically because that pattern was already found and removed from both
create routes.

**Fixed.** The route uses `_read_capped(upload, documents.MAX_FILE_BYTES)`; an
oversized attachment now costs one 64 KB chunk and a 413.

### E7 · MEDIUM · An expired JWKS cache discarded good keys and stalled the whole tier
`auth._jwks` re-fetched past the TTL with no `try`, so during a Clerk outage it
(a) threw away still-valid cached keys instead of serving the ten-minute grace its
own module docstring promises, (b) never re-stamped the timestamp, so **every**
subsequent request performed its own blocking 10-second fetch — and `require_tenant`
is called from `async def` handlers, so those seconds were taken off the event loop —
and (c) 401'd every signed-in user simultaneously, including tokens that had
validated minutes earlier.

**Fixed.** Fresh keys are served from cache; a past-TTL refresh is attempted at most
once a minute; a failed refresh serves stale within the documented grace window and
only after that fails closed, with the reason. Fail-closed is preserved: the grace
expires, and it is bounded.

### E8 · LOW · An aborted ask was never metered or traced
The metering and `observe.trace` sat *after* the `try`, so `GeneratorExit` — a
`BaseException`, invisible to `except Exception` — skipped them while the retrieval
already in flight ran to completion in a worker thread and was genuinely paid for.
The Stop button is a designed control (`App.tsx handleStop`), so `/api/usage`
under-reported exactly the asks a user cancelled.

**Fixed.** Bookkeeping moved into `finally`, with no yielding in it. It also now
distinguishes three outcomes instead of pretending: completed, errored, and
"client disconnected before the answer completed".

### E9 · LOW · A phatic or chat reply was metered as if it had cost inference
Now that a greeting costs no model call, recording `len(question) // 4` prompt
tokens against it would have overstated spend. Phatic asks are recorded as the
interaction they are, at zero tokens.

### E10 · LOW · The router's general-chat branch orphaned the citations prewarmer
`prewarm` starts before the router runs; the chat path cancelled the racers and
returned without joining or cancelling it, so a reply that retrieved nothing still
fanned a full document dump across an 8-worker pool against the brain service —
delaying citations for every concurrent ask in the process.

**Fixed.** The branch cancels the prewarmer and swallows it, like the racers.

### E11 · LOW · The rate-limit bucket map grew without bound
`_RATE_BUCKETS` is keyed on identity, then on a **caller-influenced** `Authorization`
prefix, then on client host, with no cap and no sweep — while `citations.py` has
`_bound()`, written for exactly this class with the comment "an unbounded map is a
memory leak per unique name".

**Fixed.** Idle refilled buckets are pruned past 4096 keys, with a hard clear as the
last resort; a loopback tier can no longer be inflated by header churn.

### E12 · reported, not fixed · the citation collision table is written and never read
`citations.py:116-137` records two documents sharing one fingerprint under
`manifest["_collisions"]`, with the comment that a collision must be shown rather
than guessed. **No reader ever consults it** — all three resolution sites take the
single name the dict happens to hold. Two contract headers identical in their first
120 whitespace-normalised characters therefore cite the wrong file, and
`GET /api/source?name=…` hands back the other document's text as the evidence.

Left for you deliberately: measured today there are **zero** collision groups across
9 datasets / 13 fingerprints in the local state and 12 distinct fingerprints in
`corpus/`, so this is latent, and the fix touches all three resolution paths plus the
excerpt shape — a change I do not want to land blind, in the one subsystem the product
invariant lives in. Recommendation: resolve to `None` (as E3 does) when the
collision list has more than one name, and gate it with two same-prefix fixtures.

### E13 · reported, not fixed · a REBUILD job can never publish
`lifecycle.py:438` requires `brains.state == 'CREATING'` for the publish fence. A
rebuild targets an existing, `READY` brain, so the fence fails by construction,
recovery repeats the same test at `:601`, and after `max_attempts` the job hard-fails
`RECOVERY:UNRESOLVED` with the new generation stuck in `BUILDING` — while the brain
keeps serving the old one. `is_rebuild` is computed and used only for bookkeeping.
`ops/rebuild_brain.py` promises the opposite, including a `RETIRED` state nothing
ever sets.

Behind `KESTREL_JOBS_V2=1` and an ops script, so it is not live today. Left as your
call because weakening a publish fence is exactly the kind of change that should not
be made while nobody is watching the job state machine, and E4 has just shown what
assumed ownership on that subsystem costs.

## Part 2 — the interface

### U1 · HIGH · "Add documents" on a brain row silently re-filed the conversation you were reading
`App.tsx` set the new brain, left `?chat=` in the URL and left the turns in state.
The next question saved brain A's thread under brain B — the server re-stamps the
brain unconditionally (`storage.py:341`). It also wrote `?view=chat`, the one param
`openView` exists to *delete*. `handleBrainChange` carries the comment explaining
this exact hazard and applies the full teardown; this call site skipped all of it.

**Fixed.** It now aborts the in-flight stream, fences `botIdxRef` at `-1`, clears
both the ref and the state, drops `?chat`, and goes through `openView`.

### U2 · HIGH · "New chat" and "Clear conversation" did not abort the answer in flight
`newChat` cleared the conversation without `CONTROLLER?.abort()`, without
`botIdxRef.current = -1` and without clearing `turnsRef`. One shared index means the
old stream and the new question both write to index 1: the abandoned answer
overwrote the new one, the composer flipped back to "Send" mid-question, the new
turn's working timer froze, and a half-streamed answer was then **persisted** by the
old ask's `finally`.

**Fixed.** All three guards, the same fence `handleBrainChange` documents.

### U3 · HIGH · Destructive confirms armed and never disarmed
`Sidebar.armOr` set `armed` with no timer, no outside-click and no Escape handler.
A first click you walked away from left that row permanently one click from firing —
including *delete every chat in this brain*, up to 500 threads. Every sibling already
does it right (`App.tsx` clearArmed: 3.5 s + Escape; `BrainsPage`: 6 s + unmount
cleanup), which is what makes this an oversight rather than a style.

**Fixed.** 4-second timeout, Escape, capture-phase outside click, and unmount
cleanup. The same bypass existed on the brain switcher's armed row in `App.tsx`
(Escape did not clear it) — now cleared alongside the others.

### U4 · MEDIUM · The OAuth return landed on Connectors with a URL that said chat
`setView("connectors")` with no `?view=` written, so Reload or Back dropped the user
into the chat they had left, and there was no history entry for the navigation at
all. The server controls that URL (`app.py:1293`), which is why no client-side
`openView` had ever run.

**Reported, not fixed.** The defect is confirmed at `App.tsx:624-640` — the handler
applies `setView("connectors")` and then rewrites the URL without it. The fix is one
`u.set("view", "connectors")` inside the existing branch, but it was not landed before
commit and is listed in the next-actions below, not claimed here.

### U5 · MEDIUM · The bundle guard went permanently blind on a tab opened in the background
`index.html` returned from the hidden-tab branch **before** incrementing its counter
and **before** re-arming the timer. A ⌘-clicked link therefore stopped being watched
at the first tick, and when the user finally looked at the tab it was a blank page
with neither a reload nor the explanation panel. The premise was also shaky: hidden
tabs are throttled to ~1 s, not frozen, so the chain would have carried on anyway.

**Fixed.** A hidden tab keeps polling on a larger budget instead of terminating the
chain. No browser gate ships for it: the phatic-in-the-browser gate written alongside
this pass produced four failures whose cause was not established inside the time
available, and a gate nobody has proven trustworthy is worse than none — the same
false-green class this round's own harness review was about. It was withdrawn before
commit; `tests/test_phatic.py` (38 checks, including a live route call through
`TestClient` proving the template answer with `refs: []`) is what covers E1/E2/E3. The reload cooldown, the 4xx/5xx evidence rule and the `Promise.all` verdict
are untouched — a hidden tab is now watched, not trusted.

### U6 · MEDIUM · `FilesSheet`'s progress reader swallowed every failure and reported success
`res.body!.getReader()` with no `res.ok` check, and a `catch {}` that says "sheet
closed or network dropped". A refusal body parses fine, matches none of the four
branches, and the loop simply drains to EOF — so after "Add documents" the progress
line froze and then **reported success** on a stream that had been 403'd or 503'd.
The identical reader in `App.tsx` carries the comment explaining why the guard is
needed, and the same file surfaces `data.detail` three lines earlier for the POST.

**Fixed.** Status is checked before reading, and a refusal is surfaced as the failure
it is instead of a completed success.

### U7 · MEDIUM · Nineteen translation keys used by the UI exist in no locale
Verified by key-set diff across all six `DICT` blocks: the locales are otherwise
exactly 154/154 identical with zero duplicates — but these 19 keys are in none of
them, so `t()` falls through to the caller's literal and the string is permanently
English. Two of them are typos of keys that *are* fully translated:
`up.per_month` (real key `up.per_mo`) and `upg.note` (real key `up.note`) — a
typogram paying for itself with English in German, Hindi, Spanish, French and
Chinese.

**Fixed** the two typos, which are the ones that were silently discarding existing
translations. The remaining 17 (`conn.*` for the whole Slack/Gmail import panel,
`set.connectors`, `usage.loading`, `view.show_all_n`, `chat.deleted`, `a11y.*` and
friends) are **reported**: adding them means 17 × 5 real translations, which is a
localisation pass, not a defect patch, and machine-guessed strings in a product whose
whole claim is honesty about sources is the wrong way to do it.

### U8 · MEDIUM · Whole components bypass `t()` — in a six-locale product
`GraphView` (0 calls), `CreateBrainDialog` (0), `SlackAccessDialog` (0), most of
`Connectors` and `BrainsPage` render chrome strings directly, and 34 of 43
`toast.*` calls pass raw English. The decisive evidence that this is oversight, not
policy: several bypassed strings **already have** all-six-locale keys
(`graph.title`, `action.copy`, `up.label_name`, `composer.send` / `composer.stop`).

**Reported, not fixed** — same reason as the tail of U7: it is a sweep across five
components with no test to prove each substitution, and it is a task worth doing on
its own rather than inside a bug hunt.

### U9 · MEDIUM · The email approval gate could be double-clicked into two emails
`DraftBox.send` set no state and checked none, and the `disabled={busy}` it did pass
means "the draft is still generating", which is false by the time the box is
readable. Every other POST surface self-gates. This one is the explicit approval
gate, so the duplicate is a message the user approved once.

**Fixed.** In-flight guard, button disabled while sending, and a "Sending…" label so
the wait is visible rather than mysterious.

### U10 · MEDIUM · Three primary controls were mouse-only, and one is also dead for mouse users
The collapsed working-log header (`App.tsx`) is a `<div onClick>` with no role, no
`tabIndex` and no key handler, so a finished log can never be re-opened from the
keyboard; the brain folder row in `Sidebar` is the same shape; an attachment chip is
a `<div>` calling `window.open(data:…)`, which current Chrome and Safari block as a
top-level navigation. The correct implementation already exists in this codebase and
is simply not used (`Animations.tsx` gives that same header `role="button"`,
`tabIndex` and Enter/Space).

**Reported.** The fix is to use the existing correct component, which is a real
change to markup three screens depend on; it is next in line after this pass, not
squeezed into it.

### U11 · MEDIUM · Dialogs claim `aria-modal` and never move focus
`SourceModal` and the Usage/Upgrade modals announce `aria-modal="true"` with no focus
transfer, no trap and no restore, so a keyboard user pressing Enter on a citation
chip is told "Answer ready" and then finds focus still on the chip, with the rest of
the document hidden from the a11y tree. `FilesSheet` has no dialog semantics at all
and ignores Escape. `CreateBrainDialog`, which uses Radix, does all of it correctly —
the pattern is in the tree.

**Reported.** Fixing it properly means focus refs and restore in four components;
half-doing it (e.g. focusing the panel and leaving no restore) would trade one bug
for a worse one.

### U12 · LOW · A blob URL leaked per pending image per keystroke
`URL.createObjectURL(f)` inline in the composer's render, with no revoke, while the
composer re-renders on every character.

**Fixed.** `useObjectUrls` creates once per file list and revokes on change and
unmount — the discipline `downloadFile` already applies.

### U13 · LOW · The Connectors import panel escaped its own page container
The max-width wrapper closed before the section opened, so on a wide window
"Import history into a brain" runs edge to edge while the two cards above it sit in a
centred column. **Reported, not fixed.** Confirmed at `Connectors.tsx:252-254`: the capped wrapper
closes before the import section opens. One-line markup move, not landed in this pass.

### U14 · LOW · `CreateBrainDialog`'s poll never stops and its state never resets
A 5-second `setTimeout` chain with no cancellation on close or unmount, re-polling
forever if the job read returns null, and `jobId` / `name` / `files` never cleared
while the component stays mounted hidden — so reopening "New brain" can show the
previous attempt's name, its file list, and a permanently "Working…" button.

**Reported for now.** The visible stuck state needs `KESTREL_JOBS_V2=1`, which is off
on every deployment today, and the same subsystem is what E13 leaves to you; the two
should be settled together rather than one under the other.

### U15 · verified, not a bug
`?view=chat&new=1` from `/upload` was flagged as opening a create dialog that nothing
opens. Checked directly: `/upload` redirects to `/?view=brains&new=1`, `new` is read
only to start a fresh conversation, and `newChat` now closes the dialog and the
sheet explicitly. The stale comment is in the retired legacy shell, not in the live
path. No change made.

## How each claim was held to account

- Both hunter reports were re-read at the cited lines before anything was believed;
  the one place where a report handed me a name that does not exist (`mark_down()`
  as an app-level function; the real call is `storage.mark_down`) became a
  `NameError` caught by importing the module, not a fix that shipped.
- E1 and E2 were proven with an AST walk over the route, not by reading order.
- E1/E3's detector changes were diffed against the **previous** implementation over a
  70-case corpus: zero coverage lost, zero real questions newly swallowed, eight
  genuinely social strings ("my bad", "no problem", "no worries", "it's ok",
  "thanku", "nice one", "good bot", "that's ok") newly recognised — the last of which
  is why the fail-open rule is asserted per message, not trusted.
- U7's key claim is a set difference over all six locale blocks, and the 154/154
  parity is stated precisely so the 19 are not confused with a locale gap.
- One first draft of the new tier's own invariant check was wrong: it searched for
  `cache|memo` and failed on the string `memory_layer` in a docstring. Tightened to
  real caching primitives, because a gate that cries wolf is a gate someone turns off.
- Every fix in the streaming path keeps the terminal `stage: "done"` event on both
  the success and the error branch; the client's read loop waits for it, and an early
  return that forgets it hangs the UI instead of failing it.

## Verification

`./verify.sh` against the lab after every fix: **ran 17 tiers, skipped 1
(clerk-gate, opt-in), failing 0** — that was this round's count, and the battery has
grown since (see `docs/FIX_LOG.md`; the current number is whatever the run prints, not
what any document says) — including the new `phatic` tier at 38/38, the
`ui-react` browser suite clean with zero console errors, and the 16 graph gates from
the previous round still green. `tests/test_phatic.py` runs standalone and refuses a
`DATABASE_URL` that is not the lab, so it cannot reach the live database or spend real
inference. CI needs no new step: `--quick` invokes the phatic tier already.

## What I would do next, in order

1. E12 — make an ambiguous fingerprint resolve to nothing, with two same-prefix
   fixtures as the test. It is the only remaining hole under the citation invariant.
2. U8 + the tail of U7 — one honest localisation sweep, six locales, with a gate
   that fails when a component renders a string `t()` has no key for.
3. U10 + U11 — reuse the a11y-correct components that already exist rather than
   writing new ones.
4. E13 + U14 together, as one job-state-machine pass, since they are the same
   subsystem and one of them is your decision.
5. Push and watch CI: E1–E11 and U1–U7 are all covered by tiers that CI already
   invokes, so the next green run is the proof.
