## 3. What was built, defect by defect

Anchors are current line numbers at `a78162e`.

**A-74 — a citation could open Kestrel's own demo document for a paying customer.**
`/api/source` looked up `corpus/<filename>` on disk *before* consulting the authorised brain
(`app.py:2228-2233` ran ahead of the durable lookup and the tenant read). `corpus/` is shared
by every dataset and its files are named like real documents (`05_policy_SLA-credit-01.md`),
so a tenant who uploaded a file under a corpus name got demo text back. Reproduced before the
fix: the tenant brain returned the corpus file's **2,149 characters**.
Fix, `app.py:2236` `source()`: `corpus/` is reachable only when `dataset == DEMO_DATASET`, and
the demo keeps its original order *and* its speed (the old ~20s tenant-map fallthrough guard is
preserved and asserted). A non-demo miss is now **404, never a substitution**.
Test: `tests/test_source_precedence.py`, 14 checks, always-on `source-precedence tier`
(`verify.sh:277`).

**A-75 (closes A-57) — three fingerprint defects, one mechanism.** A citation's filename is
recovered by matching the first **120 normalised characters** of content, which is not unique.
`corpus/` was last-writer-wins (two colliding files: the alphabetically later one owned both
citations); `record_upload` had written the loser into `uploads.json::_collisions` since COR-8
and **no code had ever read that table**; and an empty or whitespace-only corpus file
fingerprints to `""` — the same value a **failed** raw fetch produces, so every unfetchable
document borrowed its name.
Fix: `citations.py:71` `_corpus_fingerprints` drops ambiguous and empty fingerprints,
`:121` `_collided_fingerprints` reads the collision table, `:139` `_name_map(dataset)` is now
the single map behind all three resolver sites (replacing three duplicated
`corpus.update(_upload_fingerprints(...))` pairs). Precedence that was already right is kept:
a tenant's own upload name **beats** the demo filename for identical content.
Test: `tests/test_citation_collisions.py`, 15 checks, tier at `verify.sh:293`. It also fails
if the shipped 12-file demo corpus ever gains a colliding pair, so the strict rule cannot
silently cost a real document its citation.

**A-76 / A-77 / A-78 — citation identity.** `_durable_reference` used `limit 1` with no
`ORDER BY` while matching on a **content** key (`backend_data_id`), so the same file in two
brains matched twice and the citation named whichever row the planner reached; `durable_source`
read the *newest* `document_versions` row, so an answer produced from version A kept opening
version B after a re-upload; and the modal labelled every non-`tenant` origin "from the
corpus".
Fix: `citations.py:418` reads two ordered candidates and resolves to the brain's
**active generation**; a genuine clash (two rows inside that same generation) returns `None` →
an unresolved chip, never a guess. `citations.py:470` `durable_source(dataset, filename,
document_version_id=None)` reads exactly that version when given one and verifies it belongs
to the authorised brain; with no id the legacy newest-wins path is kept **on purpose** (every
chat saved before this has no id). The id now travels additively through `enrich()` → the
stream payload → `App.tsx` → `SourceModal` → `?document_version_id=`. No migration; the
`(brain, backend_data_id)` unique constraint is a follow-up needing a read of existing rows.
Test: `tests/test_durable_identity.py`, 15 checks over the `citations._rows:390` seam (a fake
cursor, no database), tier at `verify.sh:309`.

**A-79…A-82 — connectors.** `_states` only ever grew (reproduced: **5,001 expired OAuth state
records retained** after their TTL, until the process restarted); a token with no refresh token
and a *tracked, already-past* expiry was still handed back, so the caller took an unexplainable
401 while the row said `connected`; every refresh refusal collapsed into one answer — and
`invalid_client` / `unauthorized_client` (our OAuth client being wrong) flipped **every user's**
row to `needs_reconnect` while the HTTP status was never read; a rotated refresh token that
failed to persist disappeared behind `except: pass`, leaving the stored grant stale with no
trace.
Fix: `connectors.py:94` `_prune_states` (prune on mint and pop, `STATE_CAP` enforced *after*
the insert so the map never sits above the bound), `:629` `refresh_failure()` returning
`revoked` / `config` / `temporary` with only a revoked grant touching a user row, `:89`
`rotation_losses()` plus retry-once-then-log (truncated `%.120s`, **no token value ever
logged**), and the expired-with-no-refresh case returning `None` while an *untracked* expiry
still means "never expires" (Slack bot tokens and Google grants without `expires_in` keep
working).
Tests: `connectors_test.py` **90 → 112 checks**, lab-gated tier `connectors`
(`verify.sh:213`).

**A-83 — an outage was a denial.** `storage.brain_access` swallowed every exception into
`None`, and `brain_allowed` reads `None` as "Unknown brain", so during a Postgres outage every
authenticated user was told the brain they own does not exist — and `/api/source` 404ed for the
same reason. This **reversed a decision recorded in the code** (`app.py` SEC-2 fail-closed) and
was approved for it, because `AGENTS.md` already carries the opposite rule.
Fix: `storage.py:661` raises after `mark_down()` when the *query* failed and still returns
`None` for a successful no-row read; `app.py:401` maps that to **503, retryable**;
`citations.py:390/470` propagate a real DB error but treat `UndefinedTable`/`UndefinedColumn`
as "no durable rows" (an unmigrated volume is not an outage); the route answers
**503 "source temporarily unavailable"** and never falls through to a different document.
Auth-off behaviour is unchanged, and mid-stream durable failures still degrade to an
unresolved chip rather than breaking the answer.
Test: `tests/test_storage_outage.py`, 17 checks on a stubbed connection, tier at
`verify.sh:324`. `route-authz` and `auth-isolation` still pass — that is the evidence the
denials did not loosen.

**A-84 / A-85 / A-86 — frontend.** `FilesSheet` was the one overlay with *no* dialog semantics
at all (no `role`, no `aria-modal`, no label, no Escape, and Tab walked straight out into the
page behind); `SourceModal` and the two `km-sheet` dialogs declared the role but did none of the
focus handling; the OAuth return pad called `setView("connectors")` so the screen moved while
the address stayed on chat (a reload, bookmark or Back press put the user somewhere else with
the toast gone). And the gate written for that last one caught a defect nobody had reported:
**`history.replaceState(state, "", "")` treats an empty string as "leave the address alone"**,
so the round-trip cleanup had always been a no-op whenever the round-trip param was the only
one — observed failing as `?connected=google&view=connectors&chat=cfdd6ead-…`.
Fix: one `frontend/src/lib/utils.ts` `useDialog` hook (Escape with
`stopImmediatePropagation`, Tab containment, focus lands on the panel, focus returns to the
opener when it is still mounted), applied to all four surfaces; `openView` used for the landing
with the param cleanup done first and built from `location.pathname` + query. **No Radix port**
— this surface drives uploads; consolidation is a logged follow-up.
Tests: 14 new gates in `check_ui_react.py` (6 dialog, 8 OAuth, each re-checked after a reload),
run by the `ui-react` browser tier. `dist` rebuilt in the same commit.

**A-87 (closes A-58) — a REBUILD job could never publish.** Both fences required
`brains.state == 'CREATING'`, while `stage_rebuild()` deliberately leaves a live brain `READY`
so a failed rebuild cannot break a company brain. Every rebuild therefore ended
`RECONCILIATION_REQUIRED`/`PUBLISH_FENCED` or `RECOVERY:INVENTORY_INCOMPLETE`.
Fix: `lifecycle.py:249` `_publishable(state, is_rebuild)` — a create keeps its double-publish
guard untouched, a rebuild publishes from `READY` and still refuses `CREATING`/`FAILED`; the
recovery query now selects `kind`.
Test: `tests/test_rebuild_publish.py`, 9 checks, tier at `verify.sh:337`. It also greps the
module to fail if either fence re-opens with a literal state comparison, because no other tier
executes either path. **No lifecycle job was run end-to-end** — see §8.

**Tenancy (B05/B06/X-USAGE) — demonstrated, unchanged.** `storage.py:393` `_owner_clause`
gives every authenticated identity the `(org_id IS NULL AND created_by IS NULL)` arm,
membership **or** creator is enough, and `usage_summary` counts brains nobody registered.
`tests/test_legacy_visibility.py` (6 checks, tier at `verify.sh:352`, labelled
"characterisation only" in its own output) pins all of it so a future change is a decision.
It is **not** a security gate and a PASS there is a description, not an approval.

## 4. The review round — six defects found inside the fixes above

A fresh reader was handed the diff, `docs/FIX_LOG.md` and the ledger, none of this session's
reasoning. Two Critical, five Important, seven Minor; **each was verified against the code
before being accepted**. All in `BUGS_AUDIT.md` Round 9 addendum (A-89…A-96).

- **A-89 (Critical)** the collision sweep matched a **32-character prefix** and deleted every
  key starting with it, so recording a clash between two "service level agreement credit
  policy…" documents also silenced a third whose full fingerprint was unique — a real source
  going missing. Fixed by storing and matching the **full** fingerprint (`_collisions` key is
  now `{dataset}::{fp}`; legacy short keys are ignored, and A-57 measured zero such records).
- **A-90** `document_version_id` was shape-checked with a hex regex admitting `12345678`;
  against a `uuid` column Postgres raises a type error, which S8's own contract reads as a
  storage failure → **one query parameter could return 503 and mark `/health` down**. Now a
  UUID check, and the tier asserts no query leaves the process.
- **A-91** S8 made "this volume has not run migration 0002" a permanent 503 on every tenant
  source read. `UndefinedTable`/`UndefinedColumn` now answer "no durable rows"; only a real
  failure marks storage down.
- **A-92** a pinned citation could still fall through to the version-agnostic tenant read when
  its version row was missing — the substitution the pin exists to prevent. Now 404.
- **A-93** S3 × S6 interaction: the provenance index is unique **per generation**, so once
  rebuilds could publish, "two matches means ambiguous" would have stripped durable provenance
  from every rebuilt brain. Active generation preferred.
- **A-94** three gates were weaker than their claim (the fence guard counted call sites
  anywhere in the file; the browser gate proved "Connectors rendered" by the composer being
  *absent*, which a blank page passes; the tenancy lane implied end-to-end visibility), plus
  `stopPropagation` letting one Escape close two overlays, an unbounded provider string in a
  log line, and a colleague's document in a shared brain labelled "from your upload".
- A claim **I had written into code comments, the OpenAPI note and the ledger was false**: the
  two 403 details are not "byte-identical". `"Unknown brain."` (`app.py:427`) and
  `"This brain belongs to another workspace."` (`:435`) differ, and that difference *is* the
  enumeration oracle `docs/ACL_AND_MCP_BLUEPRINT.md` lists as Phase 1A's first job. S8 changed
  neither denial; the tier now asserts they still differ, so unifying them later has to be
  deliberate.

**Lesson for whoever continues: a failing-first test proves the defect you were looking for,
not the ones your change introduces.** Both review rounds this week found real defects in code
that had already gone green. Budget a review pass over the diff of the fixes, not just the
original work.

## 5. Behaviour that changed on purpose (the surface to eyeball after a merge)

1. A non-demo citation whose name only ever matched `corpus/` now returns **404** and renders
   "source unavailable" instead of showing demo text. Expected zero-to-few occurrences; the
   read-only live query that would count them was not authorised.
2. Ambiguous fingerprints and ambiguous durable rows render as **unresolved chips** rather than
   a filename. Fewer visible sources, no wrong sources.
3. During a Postgres outage: brain routes answer **503** where they answered 403, and
   `/api/source` answers 503 where it answered 404. Any client that treats a non-2xx as
   "empty" will now be able to tell the difference — which is the point.
4. `/api/source` documents `400/401/403/404/502/503` in OpenAPI and accepts an optional
   `document_version_id`. Additive; old clients are unaffected.
5. Refresh failures: `invalid_client`/`unauthorized_client` no longer flip user rows. Those
   cases now appear **only** in the server log (`kestrel.connectors`), so an operator watching
   the UI will see "connected" while nothing works — check the log before concluding the vault
   is fine.
6. Dialogs trap Tab and steal focus on open. If any flow relied on clicking straight through to
   the page behind an open sheet, it now can't.

### 11.2 The sequence, and why that order

`S0 baseline → S1 source precedence → S2 collisions → S3 citation identity → S4 connectors →
S5 frontend → S6 reproduce-only → S8 outage contract → S7 docs`. Ordered by (severity × how many
later steps assume it), with the citation path first because every later claim about a source
label depends on which resolver is allowed to answer. `S2b/S8b/S5b` exist because a review
followed.

Rules that were not negotiable per step, and should be for the next one:

1. Baseline recorded before any edit; stop if it isn't green.
2. Failing test first, and **confirm it fails for the stated reason** — not merely that it fails.
3. Smallest fix that keeps every other current path alive (reorder / add / narrow, never
   "remove the fallback").
4. Wire the new test into `verify.sh` **in the same commit**, or it detects nothing.
5. Read the named tier that can see the bug, then `--quick`; quote `ran/skipped/failing`.
6. Anything previously green that goes red → `git revert` the commit (a new commit, never a
   rebase/force-push) and stop.
7. Editing an existing test's expectation to make a fix pass is a **stop signal**, not a fix.
8. One bug = one commit, message prefixed with the defect ID, staging only edited files.
9. Every `frontend/src` commit carries `./ops/build_frontend.sh`.
